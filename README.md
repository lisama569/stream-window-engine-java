# stream-window-engine-java

本地实时事件聚合服务：事件按**事件时间**进入有界滚动窗口，在乱序、重复、多来源接入
与进程重启的情况下给出稳定、可解释、可复现的聚合结论。仅依赖 Spring Boot 与本地
文件系统，不依赖任何外部中间件、凭据或网络服务。

## 事件时间与水位语义

- 每个事件携带全局唯一的 `eventId`（去重依据）、业务键 `key`、事件时间
  `eventTimeMillis`（epoch 毫秒）、数值 `value`，以及可选的来源标识 `sourceId`。
- 窗口为固定长度 `engine.window-size-millis` 的滚动窗口，事件按事件时间归属窗口：
  `windowStart = floor(eventTime / windowSize) * windowSize`。
- **每个来源**维护单调不减的来源水位：
  `来源水位 = max(空闲标记声明的进度前沿, 该来源已见最大事件时间 − engine.allowed-lateness-millis)`。
  **全局水位 = 所有来源水位的最小值**，单调不减，表示“事件时间早于该值的事件被认为
  已全部到达”。不携带 `sourceId` 的事件归入默认来源；单路用法下全局水位就是该来源
  水位，语义与多来源能力引入前完全一致。
- 窗口结束时间 `<=` 全局水位时窗口**确定（finalize）**，结果通过监听器/REST 输出。
  窗口结果只取决于被接受事件的集合：在满足有界乱序前提（同一来源内事件两两时间差
  不超过允许迟到时长）且来源不自相矛盾（不发出比已发标记进度更旧的事件）时，
  **任意到达顺序、任意标记交错、并发提交下同一输入集合的窗口结果完全一致**。

## 多来源接入与空闲/进度标记

上游拆成多路来源同时发事件时，某一路长时间无数据会把它自己的水位停在原地，
进而拖住全局水位。为此引入**来源空闲/进度标记**（`SourceMarker`）：

- 标记内容：`markerId`（全局唯一，标记去重依据）、`sourceId`、`progressTimeMillis`。
- 语义：权威声明“该来源在 `progressTimeMillis` 之前（含）的数据已经到齐，当前空闲”。
  生效后该来源水位抬到 `progressTimeMillis`，不再拖住其它来源已满足条件的窗口结算。
- 来源恢复发数据时自然接回：事件时间 `>` 全局水位的事件正常计入；
  事件时间 `<=` 全局水位（已确认过期）的事件判 `LATE_REJECTED`——可区分结论，
  不静默丢弃，也不静默计入，更不会改动已定版的窗口结果。
- 标记是权威声明：来源不应发出比已发标记进度更旧的事件；若发出，该事件会被
  可区分地判为迟到。

### 标记处理结论（`MarkerStatus`，互相可区分）

| 状态 | 含义 |
|---|---|
| `ACCEPTED` | 标记已生效，来源水位（可能连同全局水位）推进 |
| `DUPLICATE` | `markerId` 已登记过（含重启后重复提交），不重复生效 |
| `STALE` | 过期/矛盾标记：进度不超过该来源已知进度；或新来源的进度已被全局水位蕴含。不生效 |
| `BACKPRESSURE` | 来源数或标记去重表达到上限，标记未生效，调用方应稍后重试 |

## 摄取结论（`IngestStatus`，可区分，不静默）

| 状态 | 含义 |
|---|---|
| `ACCEPTED` | 已计入对应窗口 |
| `DUPLICATE` | `eventId` 已登记过（含重启后重复提交），不重复计数 |
| `LATE_REJECTED` | `eventTime <= 全局水位`，超出允许迟到范围，拒绝计入 |
| `BACKPRESSURE` | 打开窗口数、来源数或去重表达到上限，事件未被计入，调用方应稍后重试 |

## 迟到与背压规则

- **迟到**：事件时间 `<=` 当前全局水位的事件被 `LATE_REJECTED`；介于水位与已见最大
  事件时间之间的乱序事件仍被接受。
- **背压**：打开窗口数达到 `engine.max-open-windows`、事件去重表达到
  `engine.max-dedup-entries`、来源数达到 `engine.max-sources` 或标记去重表达到
  `engine.max-marker-entries` 时返回 `BACKPRESSURE`——不丢数据、不崩溃。
  水位推进会回收已确定窗口与过期去重条目，之后仍处于迟到视野内的被背压事件/标记
  **重试可以成功**；若重试时水位已越过，则得到可区分的 `LATE_REJECTED`/`STALE`。
- **有界状态**：窗口确定后其状态立即回收；事件去重条目在事件时间被水位越过后回收；
  标记去重条目在进度被水位严格越过后回收（刚生效、进度恰好等于水位的标记会被保留，
  使紧随的重复提交判为 `DUPLICATE` 而非 `STALE`）。长时间运行下内存不随事件总数
  无界增长；来源数由 `engine.max-sources` 上限保护。

## 检查点与恢复保证

- 检查点内容（格式版本 2）：格式版本、全局水位、事件去重表、未关闭窗口状态、
  已确定窗口结果、**各来源水位**、**标记去重表**。来源进度与空闲状态随检查点
  持久化，重启后重复提交事件判 `DUPLICATE`/`LATE_REJECTED`、重复提交标记判
  `DUPLICATE`/`STALE`，均不重复生效。
- 写入：序列化为 JSON 并计算 CRC32，先写临时文件再**原子重命名**，避免半截文件。
- **旧检查点兼容规则**：格式版本 1（无来源状态）的检查点按清晰规则整体迁移——
  全局水位归入默认来源、标记去重表为空，恢复后与旧单路语义完全一致；
  迁移要么整体完成要么整体拒绝，绝不只恢复一半。
- 明确拒绝（抛 `CheckpointException`，不做部分应用）：
  - 文件存在但无法解析或 CRC 校验不符（损坏）；
  - 格式版本超出可兼容范围（`< 1` 或 `> 2`）；
  - 配置 `engine.checkpoint-required=true` 但文件缺失。
  文件缺失且 `checkpoint-required=false` 时全新启动。
- 正常关停（`@PreDestroy`）自动落盘一次检查点；也可通过 `POST /api/checkpoint`
  手动触发。

## REST 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/events` | 摄取事件，body 为 `{eventId, key, eventTimeMillis, value[, sourceId]}`（`sourceId` 可省略，省略即旧单路用法） |
| `POST` | `/api/markers` | 提交来源空闲/进度标记，body 为 `{markerId, sourceId, progressTimeMillis}` |
| `GET` | `/api/watermark` | 查询当前全局水位 |
| `GET` | `/api/sources` | 查询各来源当前水位 |
| `GET` | `/api/windows` | 查询已确定的窗口结果 |
| `POST` | `/api/checkpoint` | 手动触发检查点落盘 |

## 配置项（`engine.*`）

| 配置 | 默认值 | 说明 |
|---|---|---|
| `engine.window-size-millis` | `60000` | 滚动窗口长度（毫秒） |
| `engine.allowed-lateness-millis` | `30000` | 允许迟到时长，决定来源水位位置 |
| `engine.max-open-windows` | `1024` | 同时打开的最大窗口数，超限背压 |
| `engine.max-dedup-entries` | `100000` | 事件去重表最大条目数，超限背压 |
| `engine.max-retained-results` | `10000` | 保留的已确定窗口结果最大条数 |
| `engine.max-sources` | `4096` | 最大来源数量（含默认来源），超限对新来源背压 |
| `engine.max-marker-entries` | `100000` | 标记去重表最大条目数，超限背压 |
| `engine.checkpoint-path` | `data/checkpoint.json` | 本地检查点文件路径 |
| `engine.checkpoint-required` | `false` | 启动时是否必须存在有效检查点 |

## 测试

```bash
mvn test
```

覆盖：
- 单路语义（不回归）：乱序与迟到事件（多随机种子下结果一致）、背压触发与重试、
  状态随水位回收、并发摄取与顺序执行结果一致；
- 多来源与空闲：一个来源停更时另一个来源的窗口不被压住、发出空闲标记后按时定版；
  来源恢复后晚到事件正常计入、已确认过期事件可区分拒绝；不同交错顺序与并发提交下
  结论一致；重复/过期/矛盾标记幂等且结论可区分；来源数与标记去重表触限背压；
- 恢复：重启后来源进度与标记去重不丢、重复提交不重不漏；损坏/版本不兼容检查点
  明确拒绝；v1 旧检查点按清晰规则整体迁移。

单测日志会打印来源、各来源水位、全局水位、窗口结果与去重依据（`eventId`/`markerId`），
结论可复现、失败原因可区分。
